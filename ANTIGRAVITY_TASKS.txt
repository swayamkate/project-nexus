TASK 5 - IF ANYTHING FAILS (TROUBLESHOOTING)
---------------------------------------------------------------------
  - "Migration pending" banner on the Settings page:
      the platform_settings table does not exist on the live DB yet,
      or RLS blocks the service-role read. Re-check TASK 2 step 2.
  - PUT returns 503 "platform_settings table is missing":
      same cause as above. The API detects the missing table and
      fails safely instead of crashing.
  - Settings page shows a red toast on save:
      read the message; validation errors name the exact key/value
      that was rejected (e.g. malformed hex color).
  - Public portal colors/banner not updating:
      the static portal reads settings client-side with the anon
      key; check the browser console for Supabase errors and make
      sure the RLS policy "Public read platform settings" exists
      (it is part of migration 006).

  Rollback is safe: git revert the TASK 1 commit; the portals fall
  back to hardcoded defaults when the API/table is unavailable.
